Souvenance vs Mem0

They solve different problems. Mem0 is a memory layer for developers building AI applications — an excellent one, near the top of the LoCoMo benchmark. Souvenance is a finished product for one person's life: capture, media, sleep cycles, governance, included.

Mem0Souvenance
You are…a developer shipping an app with memorya person who wants to own their memory
ShapeSDK / API (SaaS or OSS library)Complete self-hosted system: MCP server, iOS capture, pipelines, web timeline
CaptureYou build itBuilt in: share-sheet shortcut, daily voice log, perceptors, word-aligned transcription, vision, EXIF
ConsolidationExtraction pipeline per exchangeSleep cycles: nightly consolidation, weekly REM recombination, active forgetting, reconsolidation
TimeFacts with update semanticsBi-temporal graph (what was true when + when the system learned it), landmarks, prospective memory
OriginalsOut of scopeVoice/photo/video/PDF kept forever, replayable via signed links
GovernanceOut of scopeExecutable constitution, audit log, ratified persona, testament clauses
SubstrateManaged platform, or OSS you assembleOne PostgreSQL on your VPS; SQL dump = export

Use Mem0 if…

You're building a product and need user-level memory as a component. It's the right tool — Souvenance's own extraction pipeline cites Mem0's work as a reference.

Use Souvenance if…

The memory in question is yours. You want the whole loop — effortless capture to nightly consolidation to “what did I think about X last year?” — running on your own hardware, governed by rules you can read, with your actual voice preserved for the replay.
